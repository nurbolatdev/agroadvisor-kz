# ADR 0011: Agro shop directory and farmer reports

- Status: accepted by the backend developer on 17 Nov 2026 (the lead asked the developers to decide such
  questions themselves); the schema (V23) is a key decision, so the lead confirms it in the review of the PR
- Applies to: `services/backend` (`shops`), `apps/mobile` (screen 18), later `apps/admin-web` (B12)

## Context

The app shows the nearest agro shops on a map and opens the route in an external navigator (2GIS, Yandex Maps);
there is no built-in routing and no call button, the phone is only text. The shop list is curated: an admin adds
and changes shops. Farmers can only tell about a new shop, wrong information, or a closed shop.

## Decision

- **Two tables (V23):** `shops` and `shop_requests`. A shop keeps `latitude` and `longitude` as numbers; the
  `geometry(Point, 4326)` column is generated by the database (as for fields), so the entity needs no spatial
  mapping and the nearby search uses the GiST index.
- **Nearby search:** a degree box on the index (`&&` with `ST_Expand`), then the exact distance in metres on the
  spheroid (`geography`) cuts the corners. Radius 1 to 100 km (default 10), up to 100 shops (default 50), nearest
  first. The box is widened with the cosine of the latitude, kept away from zero.
- **Categories** are free codes in a `text[]` column, not a table: the set is small and not yet fixed by design.
- **Hidden shops** (`status = 'hidden'`) are never shown to farmers; a hidden or missing one answers 404
  `shop_not_found`.
- **Reports:** `new_shop` has a point and no shop; `wrong_info` and `closed` point at an active shop and carry no
  point (check constraints keep this true in the database). Limit: 10 reports an hour per farmer, every attempt
  counts. The status (`new`, `done`, `rejected`) is changed by an admin.
- **Access** goes through the `shops` feature-access check, not only the role.
- **No admin API yet:** shops are inserted by SQL or by the admin API of B12. `region_id` and `district_id` are
  optional until then.

## Consequences

- Until B12 there is no way to add a shop without SQL; the mobile screen shows an empty list on a clean database.
- Reports pile up with nobody reading them until the admin screen exists (B12); no push to the author.
- Free category codes can drift (`seeds` and `seed`); the admin form should offer a fixed list.
- The search is by distance in a straight line, not by road.

## Update (B12.3)

The admin API now exists (`/api/admin/shops`, see `docs/api/admin-shops.md`): list with hidden shops, add, change, hide and show, and the list and the decision of reports. The category codes are limited to a fixed list there. A shop may be tied to a region; the district is optional because the table of districts is empty. Deciding a report changes only its status; the shop is added or edited with separate calls.

## Rejected

- **PostGIS columns mapped in JPA:** needs a spatial library in the stack for no gain; plain `JdbcTemplate` is enough.
- **A categories table:** more schema before the product knows the categories.
- **A third-party places API (2GIS, Google Places):** paid or restricted terms, and the data about shops should be
  checked by the team anyway.
